# PrepDojo 校园网多用户内测版（`server-beta` 分支）设计与实施计划

## 总体原则

- **main 分支保持单机单用户不动**；全部改动落在新本地分支 `server-beta`。
- 改动尽量做成**加法**（新表、新端点、新开关），本地模式（`serve` 不加参数）行为与现在完全一致，保证现有 39 个测试全绿。
- 新增 `--multiuser` 启动开关（或 config `multiuser: true`）：本地开发不需要登录，服务器部署时开启鉴权。

## Phase 0：服务器摸底（实施第一步）

通过 `ssh ladd90` 只读探测（skill: ladd90-ssh，注意先建 ControlMaster 应对 tun 模式）：

- OS/内核、Python 版本（需 3.10+）、`/mnt/dataY` 空间、内存/CPU
- **Docker 是否可用**（`docker ps` 免 sudo？无则有无 sudo 可装/可加组？）——决定判题沙箱路线 A/B
- 网卡 IP（确认校园网可达）、8686 端口占用情况、能否 systemd --user

部署目录定为 `/mnt/dataY/ydf/projects/PrepDojo`（分支不上 GitHub 公开仓库，用 **rsync 同步工作树**，排除 `.venv/data/__pycache__`）。

## 1. 用户与认证体系（后端）

- 新表：`users(id, username UNIQUE, password_hash, salt, is_admin, api_key, created_at)`、`sessions(token, user_id, created_at, expires_at)`。密码用标准库 `hashlib.pbkdf2_hmac`（不引新依赖）；会话 token 用 `secrets.token_urlsafe`，服务端存储可随时吊销，HttpOnly Cookie。
- 端点：`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/me`（当前用户+admin 标志）。
- 鉴权：FastAPI 依赖 `require_user` 挂到所有 `/api/*`（除 login/health）；`require_admin` 挂到危险端点。`multiuser=False` 时中间件直接放行并视为内置 `local` 用户。
- CLI 新增：`prepdojo user add <name> [--admin]`（交互输密码）、`user list / user passwd / user del`，用于服务器上建管理员。
- **Admin 门禁**（非 admin 返回 403）：`/api/llm/config` 读写、`/api/llm/models`（会把 key 发到任意 base_url，server.py:109）、`/api/fs/browse`（暴露服务器文件系统，server.py:130）、`/api/ingest/start`、`/api/problems/generate|adapt|import_json`、`DELETE /api/sources|problems`——即整个知识库页与管理操作。

## 2. 数据隔离（schema 迁移）

- `submissions`、`quiz_attempts`、`ai_judgements` 加 `user_id` 列；新增 `card_learn_state(user_id, card_id, learned, learned_at)` 取代 `cards.learned/learned_at`（`cards.explanation` 是内容派生缓存，保持共享）。
- `db.py:_migrate()`（db.py:119）扩展：加列 + 存量数据回填 `user_id='local'`，本地老库无痛升级；服务器全新库无此负担。
- **按用户过滤的方法**（签名加 `user_id`）：`pick_cards`（3 天排除窗口按人算，db.py:234 子查询）、`record_attempt`、`record_submission`、`problem_status_map`、`wrong_problem_ids`、`learn_progress`、`mark_learned`、`stats()` 个人计数部分。
- **修 IDOR**：`get_submission`/`set_review`（db.py:433/445）校验属主；user A 不能看/点评 user B 的提交。
- 知识库（cards/sources/coding_problems/test_cases）**全组共享**。

## 3. API key 混合模型

- 服务器级 key 留在 `data/config.yaml`（管理员的），普通用户不可见不可改；`users.api_key` 存个人 key（可选填写）。
- `_llm(cfg)`（server.py:53）改为 `_llm(user)`：`LLMClient(cfg.base_url, user.api_key or cfg.api_key, ...)`——默认用站长的，填了自己的用自己的。9 处调用点（ingest/generate/adapt/review/explain/quiz×2/ai_judge/chat）统一从请求会话取 user。
- 记录用量：表 `llm_usage(user_id, day, count)`；config `llm.daily_limit_per_user`（0=不限，默认 0），超限返回 429——防某个同学脚本跑飞烧穿共享 key。
- 设置页拆分：普通用户=个人 key 填写+AI 状态；admin=全局 base_url/model/key + 用户管理（增删用户、重置密码）+ 各人当日用量。

## 4. 判题沙箱加固（安全核心）

`_run_once`（judge.py:83，Popen 在 93-100）是唯一子进程出口（编译、运行、AI 出题的参考解都走它），在此处包一层：

- **路线 A（服务器有 Docker，优先）**：`deploy/Dockerfile.judge` 构建 `prepdojo-judge` 镜像（`python:3.12-slim` + `g++`，天然带 `bits/stdc++.h`，config 的 `cpp_compiler` 在服务器上设为 `g++`）。执行改为 `docker run --rm -i --network=none --read-only --memory 512m --cpus 1 --pids-limit 64 -v <tmpdir>:/work -w /work <image> timeout -k 2 <wall>s <cmd>`。容器内读不到 `data/config.yaml`，key 泄露路径被物理切断；`_classify` 增加 rc=124→TLE。config 加 `judge.docker_image`（空=本地直接执行，兼容单机模式）。
- **路线 B（无 Docker）**：建低权限系统用户 `prepdojo-judge` 跑判题（读不到 data/）+ `unshare -n` 断网；需要 sudo 权限配合。
- 全局 `threading.BoundedSemaphore(2)` 包住判题执行，防几人同时提交 C++ 编译打满小机器。

## 5. 前端改造（无构建，保持风格）

- 新增 `#page-login` 覆盖层 + 头部用户槽（用户名/退出，index.html:155-166）。
- `api()` 包装器（app.js:5）拦截 401 → 弹登录；5 处流式调用点启动前查 `/api/me`，流中 401 提示重新登录。启动块（app.js:1084）先查会话再初始化。
- 知识库页 nav 对非 admin 隐藏；设置页按 admin/普通用户渲染不同卡片。
- 代码草稿 localStorage 键加用户前缀：`prepdojo-draft-{uid}-{pid}-{lang}`（app.js:195）。

## 6. 部署到 90 与验收

- rsync 代码 → 建 venv 装 requirements → `user add` 建管理员 → 填 `data/config.yaml`（multiuser、docker_image、g++）→ `docker build` 判题镜像 → nohup/systemd --user 起 `serve --host 0.0.0.0 --port 8686` → cron 每日 `sqlite3 .backup` 备份。
- **验收清单**：① 未登录访问任意 /api 返回 401；② 两个用户各自的错题本/学习进度互不可见；③ 普通用户访问知识库页 403；④ 提交"读 data/config.yaml 的代码"在沙箱内失败（网络/文件隔离生效）；⑤ TLE 死循环正确判超时；⑥ C++ `bits/stdc++.h` 题可判；⑦ 个人 key 用户走自己的 key（服务端日志确认）。

## 7. 测试计划

- 新增 pytest：登录/会话/401、双用户数据隔离（attempts/错题本/排除窗口）、IDOR 防护、admin 门禁 403、用量上限 429、schema 迁移（旧库回填）。
- Docker 判题测试加 marker（无 docker 环境自动跳过）；本地模式全量回归 39 项必须全绿。

## 实施顺序

Phase 0 摸底 → 建分支 → 认证+用户 CLI → schema 迁移+数据隔离 → key 混合模型 → 沙箱 Docker 化 → 前端 → 部署+验收 → 回归。每阶段跑一次 pytest，服务器端到端验收按上面 7 条清单逐项过。
